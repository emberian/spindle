How it's built

One source of truth. Everything else only reads it.

RIG is a pure Rust simulation core compiled to WebAssembly and run in your browser. The frontend — TypeScript and Three.js — never decides anything about the match. It asks the core for a snapshot and draws it. That separation is the whole architecture, and it's what makes the determinism believable.

The architecture, in one picture

Determinism is treated as sacred

Every source of nondeterminism is hunted down. Seeded RNG only — no wall-clock, no unordered iteration, no platform-dependent float drift in the sim path. The render layer is forbidden from feeding anything back into the simulation; it is strictly downstream. A given seed produces a bit-identical match anywhere, which is why a replay is a replay and not a re-enactment.

And it's enforced, not hoped for: a behavioral CI gate runs on every deploy. If a change moves the match a single bit off the known trajectory for a seed, the gate goes red and the deploy stops. Determinism isn't a convention here; it's a wall.

The renderer only ever reads the truth. It never gets to make it.

How it's actually made — honestly

RIG is built fast and iteratively, and validated by watching as much as by asserting. The development style is itself part of the experiment: parallel AI agents do isolated work in their own worktrees and converge only behind green gates — the behavioral determinism check, the test suite — so speed never gets to quietly cost correctness.

That is not a disclaimer. It's the interesting part: the project is a live experiment in humans and AI agents building a real system together, and the same discipline that makes the sport a lab — determinism, gates, watchability — is what keeps that way of building honest.
